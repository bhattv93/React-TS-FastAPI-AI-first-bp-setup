# Frontend Architecture (React + TypeScript)

Stack: pnpm, Vite, React, TypeScript (`strict`), React Router, a typed OpenAPI client
(`openapi-typescript` + `openapi-fetch`), MSW for mocks, Vitest + React Testing Library. Server-state library:
TanStack Query wrapped in hooks ([ADR-0005](../adr/0005-server-state-tanstack-query.md)). Gates:
[05-quality-gates.md](../05-quality-gates.md#frontend).

## Folder structure

| Folder | Holds | Rule |
|--------|-------|------|
| `src/pages/` | Route-level screens `<Name>Page.tsx` | Compose components + hooks; no direct API calls |
| `src/components/` | Reusable UI `<Name>/<Name>.tsx` (+ `.test.tsx`, `index.ts`) | Presentational; data arrives through props |
| `src/hooks/` | `use<Domain>.ts`: data and behaviour hooks | The only place that calls `services/` |
| `src/services/` | `<domain>Service.ts`: thin wrappers over the generated client | No React imports |
| `src/api/` | **Generated** OpenAPI types/client (`schema.d.ts`) | Never edited by hand; regenerated by `pnpm api:gen` |
| `src/utils/` | Pure helpers (formatting, validation) | No React, no I/O |
| `src/tests/` | `setup.ts`, MSW `handlers.ts`/`server.ts`, test utils (`renderWithProviders`) | Shared test infra only |
| `src/routes.tsx`, `src/main.tsx`, `src/App.tsx` | Router config and bootstrap | |

Dependency direction: `pages → components / hooks → services → api`. Enforce it with ESLint
`no-restricted-imports` (for example, `components/` may not import `services/`).

## API client

1. The backend exposes `/openapi.json`.
2. `pnpm api:gen` runs `openapi-typescript` against the exported spec (`backend` writes `openapi.json` to
   `frontend/src/api/openapi.json` in CI) and produces `src/api/schema.d.ts`.
3. `src/services/client.ts` creates the `openapi-fetch` client with the `apiBaseUrl` from the runtime
   `/config.json` (empty means same-origin; in development the Vite proxy forwards `/api` to the backend).
   Non-2xx responses become an `ApiError` built from the backend error envelope.
4. CI regenerates the client and fails on `git diff`, so a stale client cannot merge.

## Conventions

- Function components with typed props (`type Props = {...}`). Avoid `any`; use `unknown` and narrow it.
- Prefer named exports. Use one `default export` per page only if lazy routes require it.
- Accessibility first: semantic elements; RTL queries by role and label (`getByRole`), never by test-id unless
  unavoidable. `eslint-plugin-jsx-a11y` is on.
- Styling: **Tailwind CSS** (utility classes, `@tailwindcss/vite`). No runtime CSS-in-JS. Shared class
  combinations become components, not `@apply` sprawl.
- Env vars: only `VITE_*` are exposed to the bundle. **Never put secrets in the frontend.** See
  [config-and-secrets.md](../07-engineering-process/config-and-secrets.md).
- Errors: one `ErrorBoundary` at the app root, and `getErrorMessage()` in `src/utils/errors.ts` turns any error
  (including `ApiError` with its request ID) into a user-facing message.

## Testing strategy

| Level | Tooling | Scope |
|-------|---------|-------|
| Unit | Vitest | utils, hooks (`renderHook`) |
| Component | Vitest + RTL + `@testing-library/user-event` | Components and pages with MSW-mocked API |
| Contract | Generated types | Compile-time; a breaking API change fails `tsc` |
| E2E (later) | Playwright | Smoke flows against a deployed env (post-v1, after M6) |

Coverage threshold is 80% (lines, branches, functions, statements); see [quality gates](../05-quality-gates.md#coverage).
