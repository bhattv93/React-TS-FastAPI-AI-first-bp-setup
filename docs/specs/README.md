# Specs

Per-story implementation specs, one file per Jira issue: `AIFS-0001.md`. They are generated by the
`jira-story-to-spec` skill from the Jira story and its acceptance criteria, using
[../04-spec-driven-development/templates/spec.md](../04-spec-driven-development/templates/spec.md).

## Lifecycle

1. **Draft:** generated from Jira; the agent may add open questions.
2. **Approved:** a human (story owner or tech lead) reviews and sets `status: approved`. No implementation
   starts before this.
3. **Implemented:** the PR that delivers the story links the spec. Every `AC-n` maps to at least one test.
4. **Archived:** after release, the spec stays as history. Jira remains the source of truth for the
   requirement. The spec is the source of truth for *how* it was built.

If the requirement changes, update **Jira first**, then regenerate or amend the spec. Never let the spec and
Jira disagree silently.
